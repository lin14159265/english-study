# V3.2：可信保存状态与同步恢复

## 使用

- “更多”中的保存状态显示 **本机已保存 / 本机保存中 / 本机未保存 / 页面待恢复**。只有当前记录提交成功，且没有未提交修改或待确认的页面刷新，才能表示本机已保存。失败时保留上次成功提交时间，不把它当作当前修改的保存时间。
- “云同步”分别展示本机提交、当前打开期间的上次云端确认、待提交次数及当前阶段。提交次数按保存操作计数，不是生词或文章数量；未提交到 IndexedDB 的修改单独说明，不计入队列。
- 新本机修改或其他设备的新版本到达时，旧的“已同步”提示立即撤下。成功上传后还需确认本机回执、剩余队列与当前页面状态，才重新显示已同步。
- 离线、网络已连接但云服务不可达、确认超时分别显示。网络错误自动退避重试；权限、配额、登录过期及需人工处理的异常暂停自动重试，保留原批次。按提示核对规则、稍后“立即同步”，或“重新登录同一账号”。
- 等待超过 20 秒时说明阶段。请求仍未结束时，“立即同步”只安排下一轮，不启动并行上传。等待或页面刷新卡住时，可以“重新打开页面”；有未提交修改或没有持久保存能力时禁用此操作，先保存或导出备份。原 operationId 与队列保留，重新打开后继续核对。
- “重试本机保存”会重放未完成的页面刷新并提交暂存修改。资料导入等失败操作若尚未进入业务状态，仍需回到原导入预览重试，不能把队列恢复当成导入成功。
- 诊断导出保留阶段、错误代码、队列数量、提交时间与运行环境，不含账号标识、文章、答案或私人笔记。持续异常时先导出完整学习备份，再导出诊断；不要清理正式网站的数据。

## 实现与兼容

`sync-status-core.js` 统一显示证据与错误类型，`cloud-sync.js` 管理待确认状态、退避、失效监听恢复和安全重试；`workspace-store.js` 暴露持久提交、未提交修改、待刷新标记，以及轻量同步摘要。状态摘要只读取 outbox 数量、syncMeta 头和 flight 键，不读取 packs、业务快照、基线或 flight 内容；面板秒级计时不触发数据库轮询。完整同步仍沿用原事务、分块快照和持久幂等回执。

IndexedDB 保持版本 3，JSON 备份保持 version 1；没有清空、重建数据库或新增个人数据字段。退出登录保留数据，首次已有数据启用仍要求备份确认。旧标签页仍使用同一同步协议和跨页保护。新公共模块纳入 Service Worker 的完整缓存，壳版本为 `20261014-v32`。

发生 UI 回退时，可以回到 PR #14 的 `a5abb05de978d833570463b88fd23b08c72900c0`，同时发布匹配的 HTML、脚本与 Service Worker。保留 IndexedDB 与原队列，不删除学习数据；不要退回不能打开 v3 数据库的旧存储层。

## 验证边界与真机步骤

自动化使用合成私人资料及模拟云端，不访问本人真实云数据。Chromium 覆盖确认丢失后重开、两端交换记录、两个标签页、离线恢复、真实 IndexedDB 事务中断、权限/配额/凭据错误、抛错或挂起的 UI 消费者、轻量诊断与备份兼容。iPhone / iPad 尺寸仅是 Chromium 视口；真实 Safari、Google 登录和实际 Firestore 网络仍需本人验收。此前手机长时间“同步中”的具体根因尚未由真机诊断确认。

真机在正式浏览器先导出完整学习备份；以下普通操作不清理或覆盖现有数据：

1. iPhone、iPad 登录本人账号，在“云同步”核对“本机已保存”与最近云端确认。
2. 手机增加一条明确标为测试的待查笔记。检查旧“已同步”撤下，等新的确认；电脑重新打开后核对实际笔记，再反向操作。
3. 手机断网，新增另一条测试笔记；确认本机已保存与离线待同步。切后台再返回、恢复网络，等待新确认，并在电脑核对。
4. 不删除任何网站数据，关闭并重开 Safari，确认阅读位置、测试笔记与私人资料仍在。iPad 分屏重复查看状态与关闭/返回操作。
5. 若等待异常，记录当前阶段，导出同步诊断。只有没有未提交修改时使用“重新打开页面”。以另一设备实际收到内容验证结果；不只看绿色状态。

账号、配额、安全规则及故障注入使用自动化隔离环境检查，不在正式 Firebase 上制造错误。
