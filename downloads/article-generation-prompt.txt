# 英语词汇语境巩固：文章生成与网站导入提示词

把下面整段提示词复制给生成文章的 AI，同时上传当天的词表。可把【资料日期】、【批次编号】改成当天日期和编号，例如 `2026-10-01`、`day01`；未填写时，先确定文件中的词表日期，无法确定则询问我。网站不接受 PDF、Word 或普通文章直接导入，需生成配套 JSON。

## 一、实际读取词表，建立不可擅自扩展的词义约束

1. 完整读取文件，提取“英文单词/短语 + 中文释义”，保留词性和原词表的全部义项。
2. 开始写文章之前，先报告实际读取到的词表条目数、去重后的目标词数，以及无法识别的条目。不得猜测看不清的内容，也不得把计划使用的词数当作已识别词数。
3. 英文大小写不同但词条相同的，视为重复词；合并它在原词表中的全部义项，保留一条。不要合并词形相近但实际不同的词。
4. 对每个词，只能使用原词表明确列出的中文义项对应的英文含义。不得因为知道其他含义而扩展用义。
5. 多义词可选择最适合语境的一个允许义项。词性、搭配及实际语境都必须与所选义项一致。
6. 若原词表释义存疑，或者某种用法是否属于允许义项不能确定，不要强行使用；保留原释义并列出问题。可以提出核对建议，但不要把未经确认的新义项写进 allowed。

## 二、组织自然的 CET-4 阅读材料

1. 整体难度控制在大学英语四级阅读水平附近。除目标词外，尽量使用四级常见基础词，不用大量高级词、罕见习语或复杂长句增加负担。
2. 每篇有明确主题、逻辑和信息内容，上下文能帮助推断目标词义。不得堆砌单词、编造荒诞情节或使用罕见搭配凑覆盖率。
3. 目标词约 150–250 个时，优先组织成 3–5 篇主题相关或相对独立的阅读文章；词数明显更少或更多时，按实际需要调整篇数。不要把近 1000 个词硬塞进 3–5 篇短文。总长度服从自然表达与准确覆盖。
4. 优先考虑大学生与教育、科技、社会生活、环境与城市、职业与就业、科学研究、文化与个人成长等题材，但主题必须服从词义。虚构的训练场景不要冒充真实新闻或真实研究结论。
5. 每篇分成便于阅读的自然段，并提供与英文**逐段一一对应**的中文参考译文，不要合并、错位或遗漏译文段落。

## 三、目标词使用与标注

1. 尽可能覆盖全部目标词，每个词原则上自然出现至少一次。适合的高价值词可以出现两次，避免机械重复。
2. 允许正常语法所需的屈折变化，如 succeed → succeeded、vary → varies、measure → measured；不能用词根相同的其他派生词代替目标词，例如 success 不能算作 succeed 的覆盖。
3. 每一次目标词的使用都要记录其所属文章、段落、实际词形和实际中文用义。不能只记录“这个词出现过”，也不能用词表全部义项代替当前语境的具体用义。
4. 可读版本的英文正文中，每个目标词在**每篇文章第一次出现**时加粗，不直接附中文释义。JSON 的 en 必须是纯文本，不写 HTML 或 Markdown 加粗；网站会根据 uses 自动加粗并提供点词解释。
5. 未使用的词必须保留在完整词表中，并给出具体原因。不要删除难用的词来伪造 100% 覆盖率。

## 四、逐词核查并修正

写完后实际逐个核对原词表，检查：

- 是否真实出现在最终正文中；实际词形是否为本词允许的语法变化；
- 实际含义是否属于 allowed 中的义项，词性和搭配是否一致；
- 是否自然、是否有足够语境，不靠译文掩盖错误；
- 每条 uses 是否指向正确的文章和段落，form 是否与最终正文的实际拼写一致；
- 译文是否保留目标词在这里的准确含义，是否逐段对齐；
- 去重目标词数、实际覆盖数和未使用数是否一致。

发现用错义项、非常生硬或漏用的词，先修改文章和译文，再重新检查所有受影响记录。若确实无法准确自然地使用，说明未使用原因。

生成《目标词使用核查表》，包含**全部目标词**：

| 单词 | 是否出现 | 位置与实际词形 | 文章中的实际含义 | 词表允许的中文义项 | 是否一致 / 未使用原因 |
| --- | --- | --- | --- | --- | --- |

不把未使用的词标记为“一致”，不声称网站能够自动判断词义是否正确。

## 五、提供可选阅读理解小测

每篇配套 3–5 道 CET-4 难度附近的四选一单选题，网站只在我主动打开小测时显示。题目覆盖主旨、信息细节、上下文词义等；不强行增加所有类型，不考偏题或词表之外的目标词义。

1. 每题只能有一个明确正确答案；四个选项都应清楚、简短，使用常见英语。干扰项应合理，但不能与正确答案同样成立。
2. 必须能仅凭文章回答，不要求外部知识或揣测作者意图。不要把“原文没说”当作“原文证明错误”。
3. 每题逐一核查正确答案及三个干扰项，发现多解、无解或证据不足时主动重写。
4. 提供中文解析和真实原文证据：段落编号从 1 开始，quote 必须逐字来自最终正文。证据要足以支撑答案，不编造或改写引文。
5. 词义题所考目标词的正确答案必须属于词表 allowed，不能借小测引入其他义项。
6. 题目与答案分开输出，JSON 则完整保存题干、选项、答案、解析和证据。网页提交作答前不展示答案。若我明确不要小测，省略 articles[].questions；旧资料仍可正常阅读。

## 六、按顺序输出学习材料

在最初的识别数量说明之后，学习材料顺序为：

① 英文文章（题目、自然段、首次目标词加粗；不夹带中文解释）

② 完整目标词使用核查表（含未使用词及原因）

③ 按文章和段落对应的中文参考译文

④ 可选阅读理解小测（题目与答案分开，放在译文之后）

⑤ 可下载的 UTF-8 JSON 资料包

如果具备文件创建能力，请提供真实 `.json` 文件。若只能输出文字，在最后给出一个包含完整 JSON 的代码块，说明只复制代码块内部并保存为 `.json`。不得用省略号、伪链接或“其余同上”代替实际内容。若输出容量不足，应先说明并拆成多个完整资料包；不能给出被截断的文件。

## 七、JSON 格式约定（必须严格遵守）

顶层字段：

- `format`：固定为 `"english-study-pack"`。
- `version`：固定为数字 `1`。
- `id`：本批次的稳定唯一编号，例如 `"2026-10-01-day01"`；仅小写字母、数字、短横线，1–80 字符，不能是 `original` 或预留的 `original-baseline`。同一批次修订时保持 id 不变；新批次用新的 id。
- `title`：本资料包的中文标题，例如 `"10 月 1 日词汇语境训练"`。
- `date`：真实资料日期，`YYYY-MM-DD`。
- `sourceCount`：去重后的完整目标词数，必须等于 `words.length`，不等于已覆盖词数。
- `words`：完整目标词数组，每词一条，必须包含已使用和未使用的词。
- `articles`：文章数组，按阅读顺序排列。

每条 `words`：

- `word`：原始英文目标词或短语，不附编号或词性，不带首尾空格。
- `allowed`：原词表允许的中文释义，保留词性和全部义项，不自行替换为更方便的释义。
- `omission`：仅对完全未在本资料包正文使用的词填写具体原因；已使用词不填或填空字符串。

每条 `articles`：

- `id`：本资料包内唯一的稳定编号，例如 `"campus-project"`，格式限制同资料包 id。
- `title`、`zhTitle`：英文题目和中文题目。
- `paragraphs`：自然段数组，每项有 `en`（英文纯文本段落）、`zh`（该段中文参考译文）和 `sentences`（按原文顺序的逐句对照数组）。每个 sentences 项为 `{"en":"该句英文原文","zh":"只对应该句的中文参考译文"}`。请为本次生成的所有段落提供 sentences，以支持网站的逐句练习。
- `sentences` 中的英文必须逐字保留本段原文，按顺序用一个空格拼接后与本段 `en` 一致；不可遗漏、重复或改写句子。每句中文应准确对应该句，不把整段译文复制给每一句。每段最多 200 句。
- 例如：`{"en":"The room was noisy. We moved outside.","zh":"房间里很吵。我们到了外面。","sentences":[{"en":"The room was noisy.","zh":"房间里很吵。"},{"en":"We moved outside.","zh":"我们到了外面。"}]}`。
- 不使用 HTML、`**`、注释或空段落。英文原文、逐段译文及逐句译文都不能包含给单词直接附加的中文释义。网站会按需显示参考译文。旧版资料包可以不含 sentences，网站会明确显示“本段参考译文”，不会假装提供逐句答案。
- `uses`：该篇文章的全部目标词使用记录。
- `questions`：可选小测数组，本次默认每篇 3–5 道。每题有唯一稳定 `id`（小写字母、数字、短横线），`prompt`（英文题干），`choices`（恰好四项，每项有唯一选项 `id` 和英文 `text`），`answer`（正确选项 ID），`explanation`（中文解析），`evidence`（至少一项，每项有从 1 开始的 `paragraph` 和逐字原文 `quote`）。答案引用选项 ID，不引用排列位置。新生成文件不要自行编造 sourceSignature；网站会绑定正文版本。
- 示例：`{"id":"noise","prompt":"What was the problem?","choices":[{"id":"a","text":"Noise."},{"id":"b","text":"Cold air."},{"id":"c","text":"A broken door."},{"id":"d","text":"High prices."}],"answer":"a","explanation":"原文直接说明房间嘈杂。","evidence":[{"paragraph":1,"quote":"The room was noisy."}]}`。此示例仅适用于正文确有该句；为实际文章重新出题和引用证据。
- `questions` 最多 20 题；没有题目的旧版资料不需要改格式版本。

每条 `uses`：

- `word`：对应 `words` 的原始词条，不填屈折变化后的词形。
- `paragraph`：本篇中该词所在的段落编号，**从 1 开始**。
- `form`：最终英文段落里实际出现的完整词形，例如 `"measured"`。必须与正文一致，不把句中其他字符或标点包含进去。
- `occurrence`：该 `form` 在这一个英文段落中第几次出现，**从 1 开始**；匹配不区分英文大小写，按完整词或短语计算。同一段重复出现时，分别记录 occurrence 1、2……。
- `sense`：这一次出现的具体中文用义，必须属于原词表 allowed 中允许的含义。

例如 `measure` 在第 2 段以 `measured` 出现一次：

```json
{"word":"measure","paragraph":2,"form":"measured","occurrence":1,"sense":"测量"}
```

同一处英文字符不能被两条 uses 重复标注。如果词表同时包含一个短语和它的组成单词，请在不同位置自然使用并分别记录，避免重叠标注。未出现的词不能伪造 uses。

JSON 必须合法：用双引号，正确转义引号和换行，不带注释、尾随逗号、YAML 开头或解释文字。每个资料包最多 5000 个目标词、100 篇文章、每篇 100 段，文件不超过 10 MB；通常每日资料远小于这些上限。

最终核对 JSON 与可读版本完全一致，正文修订后重新计算所有 paragraph / form / occurrence，检查每个词有真实 uses 或具体 omission，并核对逐句英文拼接与整段一致、逐句中文与对应句子一致；逐题确认唯一正确答案及 evidence 的段落与引文真实对应。

**最重要的原则：词义准确性 > 覆盖率 > 文采。宁可调整文章结构或如实说明遗漏，也不要使用词表之外的含义。先确认实际识别出的数量，再生成文章。**

## 生成后如何添加到网站

1. 在网站右上角点击「导入资料」，选择 `.json`，查看格式检查和文章预览。
2. 点击「确认导入到本机」，即可在当前浏览器阅读。保存资料包原文件，方便备份和更换设备。
3. 要在手机、电脑等所有设备打开同一批文章，点击「去 GitHub 上传」，把 JSON 上传到 `packages` 文件夹，再点击 `Commit changes` 提交到 `main`。
4. 等网站发布完成，重新打开网页，或在「导入与资料」点击「检查已发布资料」。不需要手动编辑网页代码或文章目录。

本机导入不会自动上传。GitHub 资料文件是公开的。网站校验的是结构与位置，无法自动保证词义正确；上传前仍需查看核查表。
