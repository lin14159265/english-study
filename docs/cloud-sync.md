# 完整个人数据同步

此分支建立在 PR #1 的 `de67b75` 上。GitHub Pages、原生 JS 与本地 IndexedDB 保留；默认 `firebase-config.js = null`，普通阅读无需登录。配置 Firebase 后，Google 登录同一账号同步阅读、已读、全部学习历史/卡片/错句/草稿/小测/任务/设置、本机私人资料包、个人修订和恢复回退快照。公开 GitHub 资料仍通过原发布目录加载，不上传公开缓存；其个人修订属于私人数据。

配置步骤见 [firebase-setup.md](firebase-setup.md)。真实项目、Google OAuth 与真机验收未完成时，不能称正式站点已经实现可用云同步。所有自动测试使用合成记录与隔离 origin，不访问正式网站个人数据。

## 保存与迁移边界

- IndexedDB 原地升级 v2→v3，新增 `syncOutbox` 和 `syncMeta`；不清空已有 stores。旧页面遇到版本变化关闭旧句柄，明确提示重开，不能继续旧式写库。
- state、私人包、恢复/回退与持久 outbox 同事务提交。服务器确认后仅删除此 flight 捕获的操作 ID；期间新增操作继续排队。flight 本身在发网络请求前持久化，未知网络结果重试相同 operationId。
- Firestore 分块、不可变清单与永久 receipts 保留；head 与 receipt 通过服务器事务检查基础版本并原子发布。已确认旧操作不会因其他设备推进 head 而再次上传。
- 本机已有记录第一次绑定账号需先导出并验证完整备份，在云同步窗口确认。云端空白不覆盖本机；新设备登录后自动恢复。一个浏览器数据库只绑定一个账号，换账号不能将上一账号数据上传；退出登录保留记录，共用设备使用独立浏览器个人资料。
- 三方合并以已确认云端快照为基线，不用设备时钟任意覆盖。独立记录自动合并；同记录修改、删除与修改、私人包或修订冲突均保存双方完整替代方案并暂停提交。窗口可明确选择冲突本机或云端版本，不冲突内容继续合并。云端不可变旧版本和本机 `syncMeta.recovery` 保留恢复副本，不自动清理。
- 云端应用后通过所有已确认消费者刷新资料/阅读/学习/工具内存。短暂事务与刷新期间暂停编辑，避免已输入草稿被重载覆盖。消费者失败保持写入保护，可在保存状态窗口重试；已确认操作不会因此重复上传。
- 仅确认本机已提交的上传时，原子更新同步基线与回执，不重写资料包、不推进业务 head、不重新加载界面；真正收到业务变化才走完整应用。同步元数据中的大快照独立保存，普通本机写入只访问轻量身份/序号头，事务一致性不变。失败恢复期间仍可下载完整 JSON 备份。
- 上传至少间隔 5 秒，按本机提交、远端 head、联网和窗口恢复触发；60 秒轻量 head 检查补偿通知丢失。离线继续本机保存，配额/网络/认证失败保留 outbox 并显示真实状态。

## 阅读与备份兼容

稳定文章键不依赖目录数字。语义锚点保存在可选 `reader.anchorKeys[articleKey]`，包含 version、正文内容版本、段落索引、UTF-16 字符偏移、前后文本、viewportOffset、scrollY 与检查点时间；正文变化先找唯一上下文，无法可靠定位时用旧像素回退。resumeKey 与明确 URL 的当前文章分开，固定 `#article-02` 仍直达；缺失或延迟资料保留记录。

停止滚动、连续滚动 5 秒检查点、切换文章、visibilitychange 与 pagehide 及时提交；系统强制终止仍可能丢失最后未完成检查点，不会破坏之前原子提交。首页附近简洁“继续上次阅读”按钮；字号/宽度变化后恢复同一字符附近。

JSON 保持 format/version 1，旧备份无 anchorKeys 正常恢复，新备份含可选字段。旧客户端会保留稳定进度但不会使用新锚点；其备份合并可能无法合并 anchorKeys，建议用本版本恢复/导出。完整手动备份包括当前私人包和个人 state；同步身份/outbox/云端冲突元数据是设备协议状态，不放入可移植个人备份。云端恢复回退快照单独同步，既有恢复功能不删除。

## 正式上线与回退

main 发布历史显示 GitHub Pages 会自动构建，因此合并视为生产发布。未得到本人“已导出并验证完整备份”的确认，不合并 PR #1 或云同步分支。无服务账号私钥、管理凭据或个人资料提交至 GitHub。

出错先将 `firebase-config.js` 置 null（同时更新 app/SW 版本），保留本地原生阅读器及同步数据。修复账号/规则后可恢复重试。回退优先修复或回退界面与适配器，保留兼容 v3 存储层；旧 v2 代码无法打开已升级 v3 数据库，不能直接回退整个旧资源包。若确需用旧版，先从 v3 客户端导出有效 version 1 JSON，在隔离浏览器恢复验证；绝不删除正式 IndexedDB 来实现降级。

## 本人验收与隔离环境

下载该开发分支的 GitHub ZIP，解压后在电脑目录执行 `python -m http.server 8766 --bind 127.0.0.1`；仅从 `http://localhost:8766/` 测试，独立 origin 与正式站点数据隔离。备份恢复先用另一个浏览器个人资料，JSON 导入预览→恢复→核对私包、义项卡、错句、小测和任务→再次导出对比。

使用合成数据进行云端真机测试时，请用独立 Spark 测试项目，避免测试资料进入正式云端账号数据集。手机真机需同一份代码的**独立 HTTPS 域名**（独立测试托管或本人 HTTPS 隧道），将该域名加入 Firebase Authorized domains；不能把 GitHub 正式路径当隔离环境，因为同 origin 共享 IndexedDB。不要清除正式网站数据。LAN HTTP 可以测试普通导航，但不能代替 HTTPS 的 SW/Google 登录验收。生产账号配置后，测试域名及发布安排由本人完成授权。

真实手机/平板验收顺序：

1. 电脑测试环境导入合成私包，收藏义项、记错句、作答小测、留草稿、排任务、改正文、保存阅读位置；登录→备份确认→等待“已同步”。
2. Android Chrome、iPhone Safari、平板正常浏览器打开独立 HTTPS 测试站，登录同一账号；无手动 JSON 导入即可看到上述全部内容与同一句附近。
3. 手机增加生词/错句、完成小测、编辑私包；电脑重新打开自动获取，不覆盖之前其他记录。
4. 手机开飞行模式持续滚动并新增记录，切后台后重开；恢复网络自动提交，电脑获取。强制结束允许最后检查点损失，之前已提交记录必须保留。
5. 两设备离线分别编辑同一份资料或同一草稿，联网后出现冲突；先备份，再选版本，另一端恢复结果。双方旧版本不可静默删除。
6. 换完全新浏览器登录自动恢复；退出账号本机保留；其他账号拒绝同步。真实 Google/Firebase 连接失败时本地功能仍可用。
7. 在测试 origin 准备离线文件、应用 SW 更新、断网重开，保留所有记录。小屏横竖屏、字号变化核对语义位置。真机结果不得用桌面模拟视口替代。
